# 13. Кэширование

Date: 2026-09-21

## Status

Accepted

## Context

Система генерирует рекомендации по каждой из групп в отдельности, что приводит к тому, что рекомендации запрашиваются по интересам каждой группы, а эти интересы могут пересекаться. Требуется принять решение по кэшированию полученных рекомендаций.

## Decision

На этапе MVP кэширование не применяется, впоследствии добавить распределённый кэш.

## Alternatives

Кэшировать рекомендации, выработанные с помощью одного и того же набора системного/пользовательского промтов с точностью до id группы. Это позволит снизить количество затрачиваемых токенов для внешней модели (если внешняя модель сама не кэширует ввод и вывод).

## Consequences

Риск: повышенный расход на inference во внешней модели. Митигируется на первом этапе кэшированием на стороне выбранного поставщика inference.
Архитекторы решили изменить способ генерации рекомендаций и записать в техдолг введение распределённого кэша на Redis для оптимизации количества обращений к внешней модели.
