# 15. Размещение сервисов

Date: 2026-09-21

## Status

Accepted

## Context

Для работы сервисы проекта требуется разместить где-то помимо компьютера архитектора, который их кодировал. В распоряжении группы архитекторов имеется один сервер конфигурацией 8 CPU, 16 Гб RAM, 2000 Гб SSD без GPU/TPU/FPGA. Политика развёртывания внутренних разработок Яхундекс не предполагает использования внешней инфраструктуры в случаях, когда без этого можно обойтись.

## Decision

Сервисы проекта и облегчённая инфраструктура (Kafka в одноброкерном режиме и PostgreSQL в односерверном режиме) будут развёрнуты до момента передачи на поддержку на сервере группы архитекторов в контейнерах с помощью docker compose. 

## Alternatives

- Передать в виде Helm Chart-а. Этот путь будет предпочтительным в будущем и на него необходимо будет перейти, чтобы передать систему в поддержку.
- Оставить как есть - в этом случае систему пожизненно будет сопровождать команда архитекторов, что негативно скажется на остальной их деятельности (и в случае некоммерческого проекта, как этот, заставит со временем эту систему вывести из поддержки)

## Consequences

В контейнеризованном виде систему проще будет передавать на поддержку и конфигурировать после.
Архитекторы решили записать в техдолг - после обкатки системы опубликовать контейнеры в корпоративном хранилище собранных бинарных артефактов, создать Helm Chart для запуска и настроить обновление через CD.
Если система дойдёт до внешних пользователей, то необходимо будет предусмотреть UI пользователя, сетевую связанность с интернетом (через DMZ (firewall -> waf -> firewall в protected c промежуточными балансировщиками)), балансировщики на входе и по несколько экземпляров сервисов в зависимости от ожидаемой нагрузки, разворачивание БД и Kafka в кластерном режиме в нескольких ЦОД-ах (на случай, если ЦОД по различным причинам выйдет из строя).
Риск: нарушить п. 7 [НФТ ТЗ](../../docs/tz.md), митигируется принятием риска.
