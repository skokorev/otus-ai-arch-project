# 5. Стек разработки

Date: 2026-09-10

## Status

Accepted

## Context

Необходимо решить, в рамках какого стека разработки будет реализован проект подбора статей. В технорадаре Яхундекс присутствуют: 
Языки:
- Java
- C#
- Python
- JS/TS
БД:
- PostgreSQL
- H2
- MySQL (выводится в пользу PostgreSQL)
- MS SQL Server (выводится в пользу PostgreSQL)
- Oracle (выводится в пользу PostgreSQL)
- RocksDB
- Greenplum (выводится в пользу RocksDB)
- Redis community
Брокеры сообщений:
- Kafka
- RabbitMQ

## Decision

Будет использоваться стек разработки Java/Spring framework
Будет использоваться брокер сообщений Kafka
Будет использоваться БД PostgreSQL в силу небольшого выбора из имеющихся в распоряжении Яхундекса технолоний на поддержке

## Alternatives

В качестве языка/стека разработки языки Python и C# подходят не хуже Java, но стек Java наиболее знаком реализующему проект архитектору, поэтому в сжатые сроки решено использовать именно его.
В качестве брокера сообщений можно было бы выбрать RabbitMQ, но брокеры на базе журнала проще в настройке (за счёт механизма consumer group) для отложенного потребления выпущенного сообщения отдельным микросервисом (допустим, остановленного на обслуживание), таким же образом проще расширять функциональность системы (см. п. 3 [НФТ ТЗ](../../docs/tz.md))

## Consequences

В Яхундекс есть несколько стабильных команд, разрабатывающих в стеке Java, что позволит проще поддерживать сервис, в случае вывода его в Production
