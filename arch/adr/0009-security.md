# 9. Безопасность

Date: 2026-09-12

## Status

Accepted

## Context

Для обеспечения безопасности требуется выбрать способ авторизации администратором своих действий

## Decision

Будет использоваться схема Bearer Token для доступа к REST API сервиса configurator. Token получается из корпоративного KeyCloak, сынтегрированного с корпоративным LDAP. Доступ к остальной инфраструктуре (корпоративный брокер Kafka, БД PostgreSQL) обеспечивается согласно политике безопасности Яхундекс, для БД - техническая учётная запись с паролем, для Kafka - пара ключей. Все секреты будут храниться в корпоративном Vault.

## Alternatives

Использование других схем безопасности для внутренних разработок Яхундекс приведёт к перерасходу рабочего времени либо на их настройку, либо в перспективе на прописывание регламентов для L2, поэтому архитекторы решили воспользоваться тем, что есть.

## Consequences

Для L2 будет достаточно просто сконфигурировать безопасность в промышленной среде за счёт того, что принятое решение не использует особенных процедур и все остальные разработки Яхундекс выкатываются с подобными настройками.

Для внешних пользователей (в случае, если система до них дойдёт) можно добавить соответствующие политики

На этапе MVP при наличии из инфраструктуры только один сервер, поэтому PostgreSQL и Kafka будут развёрнуты локально без специальных мер безопасности (см. раздел "Срезанные углы" в [README](../../README.md)).
