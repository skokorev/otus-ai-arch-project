# 12. Стойкость к отравленным данным

Date: 2026-09-19

## Status

Accepted

## Context

Требуется определить места, где возможно отравление данных или промта и описать меры противодействия подобным отравлениям. В рамках MVP единственные данные на входе модели, которые при желании можно отравить - это аннотация (abstract) статьи. Системый промт статичен и неизменен, пользовательский в качестве подстановки содержит только id группы пользователей, формируемый системой автоматически. Поменять его можно только вручную через БД.

## Decision

В рамках MVP не добавлять специальных средств контроля отравления данных / промтов.

## Alternatives

Добавить guardrail-ы на abstract статей. Это повлечёт дополнительные расходы на разработку и увеличит её время.

## Consequences

В будущем (после MVP) разумно было бы добавить guardrail-ы на abstract статей.
Также при дальнейшем развитии системы, когда изменение системного и пользовательского промтов будет возможно за счёт администраторского или/и пользовательского ввода - добавить guardrail-ы на этот ввод.
