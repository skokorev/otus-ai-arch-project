# otus-ai-arch-project
Дипломный проект для курса "ИИ-архитектор" OTUS

## История проекта
Компания "Яхундекс" - средний бизнес (численность сотрудников более 100, но менее 500) - заметный игрок на рынке локального поиска. Все клиенты принадлежат к сектору B2B и в основном используют решения компании для поиска по витринам, хранилищам текстовых данных, хранилищам визуальных данных. В компании работают сильные специалисты, которые могут, например, сделать из Solr (или Lucene) не только то, чем можно пользоваться самому, но и то, что можно продать кому-то другому. Исходя из экспертности специалистов в области построения индексов для чёткого и нечёткого поиска, архитекторы компании, решили, что стоит попробовать свои силы на ниве построения индексов для поиска в векторных хранилищах. Для этого необходимо изучить статьи, которые описывают текущие достижения в области векторного поиска на ArXiv.org. Сайт ArXiv предлагает удобную фильтрацию статей по темам, однако объём выпускаемых статей не позволяет архиткеторам "Яхундекс" своевременно ознакомиться с ними.
Тогда архитекторы решили (здесь появляется ЧТЗ#1 ./docs/tz-1.md):
во-первых - написать ИИ-агента с использованием облачного провайдера инференса для отыскания необходимых статей и формирования групповой рассылки рекомендаций по тематике векторного поиска
во-вторых - доработать систему групповых рассылок для ранжирования подобранных статей по релевантности интересов групповой рассылки
в-третьих - представить полученную систему как POC для руководства компании с целью получения одобрения для дальнейшего развития

После оценки системы руководством (CTO, CIO, CFO и CMO) было решено (появляется ADR0 и ЧТЗ#2 ./docs/tz-2.md):
во-первых - доработать агента с тем, чтобы можно было формировать не только групповые, но и индивидуальные рекомендации
во-вторых - доработать систему для задания тем рекомендаций и множественной рассылки по схеме freemium (общие рассылки - бесплатно, индивидуальные - тарифицируются)
ожидаемый эффект - выход на окупаемость за 1 год

Архитекторы приняли ряд решений по (ADR...):
1. Разработке (исходя из своих возможностей, так как команду на разработку не дали)
2. Тестированию
3. Data Pipeline (исходя из источников данных) 
4. Наблюдаемости (без которой с самого начала ничего не получалось)
5. Безопасности (и Compliance, в основном относительно ПДн)
6. Размещению (исходя из ожидаемых финансовых показателей)
и представили решение в качестве MVP.
